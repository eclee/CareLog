# 從 CareLog 1.1.0 升級至 1.2.0

1.2.0 會增加參數設定、用藥參考圖片、結構化照片庫、操作紀錄篩選與永久異常事件。升級流程會保留既有照顧紀錄與舊照片，但任何資料結構變更都應先有可還原的備份。

## 一、升級前

1. 停止 CareLog、Waitress 或 Docker 容器。
2. 備份完整資料目錄，至少包含：

```text
carelog.db
uploads/
```

Docker 使用者應備份整個 `data/`：

```bash
docker compose stop
cp -a data "data-backup-$(date +%Y%m%d-%H%M%S)"
```

3. 確認備份可讀，並保留 1.1.0 程式碼或 release ZIP，便於必要時回復。
4. 不要在沒有備份的正式資料庫上先試跑升級。備份若沒有演練過還原，仍比較接近願望而不是保險。

## 二、更新程式與依賴

```bash
git pull --ff-only
python -m pip install --upgrade -r requirements.txt
```

ZIP 使用者請將 1.2.0 程式放在新目錄，不要覆蓋舊目錄中的 `.env`、資料庫或照片；再把 `CARELOG_DATA` 指向原資料目錄。

## 三、升級資料庫

```bash
CARELOG_START_SCHEDULER=0 flask --app app upgrade-db
```

此命令可重複執行，會：

- 補上使用者刪除時間；
- 建立用藥填報群組；
- 擴充照片中繼資料；
- 擴充操作人員快照；
- 建立異常事件及圖片關聯表；
- 建立查詢索引；
- 回填可由舊紀錄推得的照片日期、上傳者與操作人員資料。

全新安裝仍可使用：

```bash
CARELOG_START_SCHEDULER=0 flask --app app init-db
```

Docker 的 entrypoint 會在容器啟動時自動執行 `init-db`，其中包含相容性升級；即使如此，仍應先完成備份。

## 四、預覽及搬移舊照片

先預覽，不修改檔案：

```bash
CARELOG_START_SCHEDULER=0 flask --app app media-migrate --dry-run
```

確認 `scanned`、`migrated`、`missing` 與 `failed` 後再執行：

```bash
CARELOG_START_SCHEDULER=0 flask --app app media-migrate --apply
```

搬移程序會：

1. 讀取舊照片；
2. 依實際影像內容解碼；
3. 轉成 JPEG 並產生縮圖；
4. 寫入新結構化目錄；
5. 更新資料庫路徑及雜湊；
6. 資料庫成功提交後移除舊檔。

已在 `elders/` 結構中的照片會略過，因此可安全重跑。找不到來源檔時會計入 `missing`；失敗檔不會被自動刪除。

## 五、選用：重建歷史異常事件

1.1.0 沒有永久異常事件表。升級後只會自動保存新事件；需要回查舊資料時可選擇重建：

```bash
CARELOG_START_SCHEDULER=0 flask --app app rebuild-abnormal-events \
  --from-date 2026-01-01 \
  --to-date 2026-08-22
```

限制：

- 重建使用「執行當下」的異常規則；
- 舊版未保存當時門檻，因此不能宣稱是歷史當時的原始判定；
- 重建生命徵象不寄送 Email；
- 命令可重跑，相同來源與指標以事件鍵去重複。

## 六、帳號刪除差異

1.2.0 起，刪除帳號不再物理移除使用者：

- 帳號會停用並隱藏；
- 密碼或 PIN 會清除；
- 歷史照顧紀錄仍保留建立者 ID；
- 操作紀錄保留操作者快照。

1.1.0 已經硬刪除且清空 `user_id` 的舊操作紀錄，若資料庫中沒有其他身分線索，無法自動還原原使用者。

## 七、啟動與驗收

啟動服務後依序檢查：

- 管理者可進入「參數設定」並看到三個喝水快捷值；
- 新增長輩帶入預設生日與喝水目標；
- 用藥計畫可拍照、上傳、設主圖及刪除圖片；
- 照顧者用藥頁可看到藥名、劑量與參考圖片；
- 新填報圖片位於結構化目錄；
- 後台照片庫可依長輩、類型、日期及紀錄 ID 查詢；
- 操作紀錄可依使用者與日期期間查詢；
- 超標生命徵象會建立異常事件，且 Email 未設定時事件仍存在；
- 異常事件可更新為追蹤中、已解除或排除；
- 管理者導覽列顯示照片與異常入口；
- 家屬及照顧者仍可查看儀表板。

## 八、回復方式

若升級後必須回復：

1. 停止 1.2.0；
2. 移走目前資料目錄，不要直接覆寫；
3. 還原升級前完整備份；
4. 使用 1.1.0 程式碼啟動；
5. 驗證登入、資料庫與照片。

不要將已經由 1.2.0 修改過的資料庫直接交給 1.1.0，因為舊版不理解新增資料表與欄位的語意。
